# Balance — original concept design fidelity acceptance

## Audit (2026-11-26)
User supplied ten screenshots of earlier interactive concepts. Current main v0.10.0 was inspected against those references. The existing generic shell() and .panel/.item visual language is too dominant. Current code has no range inputs, no grouped Today intentions checklist, no Her world feature, no gaming-night planner, and no mood/energy/anxiety check-in or chart. Rituals use plain text rows, adventures foreground six filter selects, insights use aggregate bars and sleep duration, awards repeat five glyph paths. Solar has a five-second text-shadow animation, but it is not the intended rich contextual lighting. These are design and feature gaps, not resolved by passing browser geometry tests.

## Design system
- Warm, tactile, Nintendo-like layered surfaces with distinct purpose-specific component families. Avoid a generic panel for every feature. Restrained colored outline SVG icons, consistent stroke/rounded caps, colored icon tiles; replace generic emoji in core navigation/actions. Maintain recognizable symbols and semantic colors across tabs, modes and charts. Use accessible contrast in both themes.
- Use purposeful light: slow approximately five-second breathing halo on sun/daylight focal point; warm pools of light under string bulbs; soft rain layers and steam in cozy mode; small contextual highlights on active controls and eligible ritual opportunities; brief, optional positive celebration for real logged actions. No glowing every surface or constant movement. Respect reduced motion, maintain clear text and keep passive animation lightweight.
- Mobile first, 44px usable touch targets where feasible, compact headers, no horizontal page overflow, sticky-nav clearance, long names wrap, no unexpected iOS input zoom. Keep user-requested header layout and top-right dialog close. Use visible primary actions and hide secondary editing controls in disclosures or compact dialogs.
- Visual hierarchy: dominant glanceable value, supporting label, then secondary information. Use progress bars/rings/segmented controls only when data supports them. No score of partner affection or personal worth, no penalty for skipped routines, no red failure state for rituals. Never invent user data to fill an empty dashboard.

## Component acceptance
1. Today intentions: configurable grouped Personal foundation, Shared responsibilities, Intentional connection; checkmark rows, group counts/progress and optional total for selected intentions only; completion derives from a single underlying activity event, with explicit undo. Full/reduced/recovery changes selected routines, no guilt or compulsory default goals. Keep next meaningful plan and quick logging prominent.
2. Partner memory space (Her world is a configurable label): colored two-column tiles for little joys, replenishment, support, gift ideas, important moments, follow-ups. Owner-only data; no hardcoded names or actual personal facts. A separate access boundary is necessary before enabling sensitive records or any partner-visible view. Generic labels only in public source.
3. Little rituals: meaningful colored outline icon, relative last-done date, suggested interval progress and next opportunity, primary Did this action, compact gear/sliders. Expanded circular timer with days since, upcoming interval and weekly/biweekly/monthly/custom presets; range input for interval and optional hypothetical preview clearly separated from actual history. Saturate at suggested interval, gentle opportunity cue, never red/decay. Unlogged/paused/snoozed states distinct.
4. Don't Overthink It: suggestion first, centered icon/title, short practical description, compact budget/duration/preparation chips, another idea and plan actions. Filters secondary, sliders for budget and duration, segmented energy/setting, optional weather/daylight preferences. Do not equate estimated cost or duration with actual data.
5. Things to Look Forward To: featured next plan, actual date/time, countdown with meaningful progress only when creation date is known, explicit agreement/confirmed status rather than assuming agreement. Visual lifecycle inspired/ready/scheduled/anticipating/remembered; spontaneous plans may skip steps. Preserve linked plan and one activity record.
6. Weekly balance: seven-day colored segments showing days with logged activity, not unlogged inactivity; consistent category icons, labels and distinct-day counts. Optional last-engaged time per hobby. Descriptive reflection based only on observed entries.
7. Sleep schedule: timeline floating bars from actual reported sleep onset to wake, across midnight; separately marked partner bedtime and joined time, unknown values not inferred. Shared/separate bedtime classification only if explicitly recorded or clearly defined as time proximity, not relationship score. Missing nights blank.
8. Mood and activation: optional self-reported mood, energy, anxiety sliders with clear anchors and skip; independently colored lines with gaps for missing days, no invented interpolation or causal/clinical conclusions. Sensitive data must pass privacy gate first.
9. Gaming nights: weekly preference slider 0–7, seven selectable days, count vs planned allowance, configurable target bedtime and wind-down lead, actual sleep opportunity warning based on planned wake time if known. Not permission or punitive rule. Reminder in app only unless reliable notification mechanism established; no promises of OS notifications.
10. White Lotus: distinct semantic outline icon for each achievement, compact responsive two-column collectible cards, muted undiscovered state, subtle earned shimmer/animation, detail on tap, hidden achievements do not reveal conditions until earned. Air Temple Island should be an expressive scene rather than a generic flat card; preserve original art and no decay.
11. Solar Powered / Jasmine Dragon: strong sun/moon focal point, meaningful moving daylight arc and remaining daylight, time-to-home buffer; warm glow visible in light and dark, rain/coffee/string light scene distinct from normal night. Date-matched weather fallback and reduced motion; avoid enormous first-screen hero that hides actions.

## Release gate
Use original reference screenshots as design acceptance, not exact copies of ChatGPT UI. Review actual rendered phone and desktop screenshots for every materially changed component, both themes and 320/390/430px widths. Maintain existing owner storage keys, sync, offline behavior and record semantics. Verify visual/interaction fidelity separately from functional test counts. Keep v0.10.1 bugfix gated on CI. Implement in cohesive feature batches, not one superficial restyle. No private screenshots or personal facts in public repo. See RELEASE_GATES.md for security and native iPhone verification.
